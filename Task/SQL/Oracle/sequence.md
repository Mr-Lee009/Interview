# Oracle Sequence - sinh mã số tự tăng

`SEQUENCE` là object Oracle tạo ra dãy số duy nhất, thường dùng cho khóa chính như `user_id`, `order_id`. Sequence độc lập với bảng: nhiều bảng hoặc nhiều session có thể gọi cùng một sequence.

Khác với `IDENTITY`, sequence không tự gắn vào một cột. Ứng dụng hoặc câu SQL phải gọi `NEXTVAL` khi cần số mới.

## 1. Tạo sequence cơ bản

```sql
CREATE SEQUENCE seq_products
  START WITH 1
  INCREMENT BY 1
  NOCYCLE
  CACHE 20;
```

| Thành phần | Ý nghĩa |
|---|---|
| `START WITH 1` | Giá trị đầu tiên được sinh ra là `1`. |
| `INCREMENT BY 1` | Mỗi lần sinh số mới tăng thêm `1`. Có thể là số âm để giảm dần. |
| `NOCYCLE` | Khi chạm giới hạn, sequence báo lỗi thay vì quay lại đầu dãy. Đây là lựa chọn an toàn cho primary key. |
| `CACHE 20` | Oracle giữ trước 20 số trong bộ nhớ để cấp nhanh hơn. |

Nếu không ghi các tùy chọn, Oracle có giá trị mặc định riêng. Với ID nghiệp vụ, nên khai báo rõ `START WITH`, `INCREMENT BY`, `NOCYCLE` và `CACHE` để dễ đọc và vận hành.

## 2. Dùng `NEXTVAL` và `CURRVAL`

`NEXTVAL` lấy số mới và làm sequence tiến lên. `CURRVAL` trả số vừa lấy bởi **session hiện tại**.

```sql
-- Lần gọi đầu tiên trả về 1, các lần sau tăng dần.
SELECT seq_products.NEXTVAL FROM dual;

-- Chỉ hợp lệ sau khi session này đã gọi NEXTVAL ít nhất một lần.
SELECT seq_products.CURRVAL FROM dual;
```

`CURRVAL` không sinh số mới. Nếu gọi trước `NEXTVAL` trong session, Oracle báo lỗi `ORA-08002`.

## 3. Dùng sequence khi INSERT

```sql
CREATE TABLE products (
  product_id NUMBER(19) PRIMARY KEY,
  name       VARCHAR2(200 CHAR) NOT NULL,
  price      NUMBER(12,2) NOT NULL
);

INSERT INTO products (product_id, name, price)
VALUES (seq_products.NEXTVAL, 'Keyboard', 500000);

COMMIT;
```

Lấy ID vừa insert trong cùng session:

```sql
SELECT seq_products.CURRVAL AS new_product_id
FROM dual;
```

Với JDBC, thường truyền `seq_products.NEXTVAL` trong câu `INSERT`, hoặc gọi `SELECT seq_products.NEXTVAL FROM dual` để lấy ID trước. Không dùng `MAX(product_id) + 1`, vì hai transaction đồng thời có thể nhận cùng một ID.

## 4. Insert nhiều dòng

Mỗi lần xuất hiện `NEXTVAL` sẽ lấy một giá trị mới.

```sql
INSERT ALL
  INTO products (product_id, name, price)
    VALUES (seq_products.NEXTVAL, 'Mouse', 250000)
  INTO products (product_id, name, price)
    VALUES (seq_products.NEXTVAL, 'Monitor', 3500000)
SELECT 1 FROM dual;
```

## 5. Dùng trong trigger (cách cũ)

Với bảng thiết kế trước Oracle 12c, trigger thường tự gán ID nếu application không truyền vào:

```sql
CREATE OR REPLACE TRIGGER trg_products_id
BEFORE INSERT ON products
FOR EACH ROW
WHEN (NEW.product_id IS NULL)
BEGIN
  :NEW.product_id := seq_products.NEXTVAL;
END;
/
```

Sau đó có thể insert không cần `product_id`:

```sql
INSERT INTO products (name, price)
VALUES ('Webcam', 900000);
```

Với Oracle 12c trở lên, ưu tiên cột `IDENTITY` cho ID đơn giản vì ít object hơn:

```sql
CREATE TABLE categories (
  category_id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name        VARCHAR2(100 CHAR) NOT NULL
);
```

`GENERATED BY DEFAULT AS IDENTITY` vẫn cho phép application truyền ID khi thật sự cần. `GENERATED ALWAYS AS IDENTITY` nghiêm ngặt hơn: Oracle tự sinh ID và application không được truyền giá trị thông thường.

## 6. Sequence và Identity: chọn cách nào?

| Nhu cầu | Nên dùng |
|---|---|
| Một cột ID đơn giản cho một bảng mới | `IDENTITY` |
| Một dãy ID được dùng bởi nhiều bảng | `SEQUENCE` |
| Muốn chủ động lấy ID trước khi insert | `SEQUENCE` |
| Hệ thống Oracle cũ hơn 12c | `SEQUENCE` + trigger hoặc gọi `NEXTVAL` |
| Cần format mã như `ORD-000001` | `SEQUENCE` và format khi hiển thị |

Sequence/identity nên dùng cho khóa kỹ thuật. Nếu số hóa đơn, mã đơn hàng phải liên tục tuyệt đối theo luật/nghiệp vụ, cần một thiết kế cấp số riêng có transaction, khóa và quy trình xử lý hủy số; sequence không bảo đảm không có khoảng trống.

## 7. Vì sao ID có thể bị nhảy số?

Sequence bảo đảm **không trùng**, không bảo đảm liên tiếp.

Các nguyên nhân phổ biến:

- Transaction gọi `NEXTVAL` rồi `ROLLBACK`: số đã cấp không quay lại.
- Nhiều session cùng lấy số: thứ tự commit có thể khác thứ tự ID.
- Dùng `CACHE`: khi instance/database restart, các số đã cache nhưng chưa cấp có thể bị bỏ qua.
- Xóa một dòng: sequence không tái sử dụng ID đã xóa.

Không cố sửa lỗ hổng ID primary key. Đây là hành vi đúng, bình thường và giúp concurrency tốt hơn.

## 8. Cache, cycle và giới hạn

```sql
CREATE SEQUENCE seq_event_id
  START WITH 100000
  INCREMENT BY 1
  MINVALUE 100000
  MAXVALUE 999999999999
  NOCYCLE
  CACHE 100;
```

- `CACHE n`: nhanh hơn cho workload có nhiều insert; chấp nhận có thể nhảy số khi restart.
- `NOCACHE`: giảm khả năng mất số do cache nhưng thường chậm hơn; vẫn không bảo đảm liên tục do rollback/concurrency.
- `CYCLE`: quay về `MINVALUE` sau `MAXVALUE`; không dùng cho primary key vì có nguy cơ đụng dữ liệu cũ.
- `ORDER`: đảm bảo thứ tự cấp số giữa các instance trong RAC, nhưng có chi phí; hệ thống đơn instance thường không cần.

## 9. Thay đổi sequence

```sql
ALTER SEQUENCE seq_products
  INCREMENT BY 1
  CACHE 50
  NOCYCLE;
```

Không thể đổi `START WITH` của sequence đã tạo. Để cấp lại từ một giá trị mới, có hai cách.

### Oracle 18c trở lên: restart sequence

```sql
ALTER SEQUENCE seq_products RESTART START WITH 1000;
```

Chỉ restart khi chắc chắn giá trị mới không trùng dữ liệu đang có. Với bảng đã tồn tại, kiểm tra trước:

```sql
SELECT MAX(product_id) AS max_product_id
FROM products;
```

### Cách tương thích phiên bản cũ

Đặt increment tạm thời để nhảy tới số mong muốn, rồi đặt lại increment chuẩn. Ví dụ `CURRVAL` hiện là `10`, muốn `NEXTVAL` kế tiếp là `1000`:

```sql
ALTER SEQUENCE seq_products INCREMENT BY 990;
SELECT seq_products.NEXTVAL FROM dual; -- nhận 1000
ALTER SEQUENCE seq_products INCREMENT BY 1;
```

Cách này nhạy cảm với session khác đang dùng sequence. Với production, dừng luồng ghi hoặc dùng kế hoạch migration được kiểm soát.

## 10. Xem thông tin sequence

```sql
SELECT sequence_name,
       min_value,
       max_value,
       increment_by,
       cycle_flag,
       cache_size,
       last_number
FROM user_sequences
ORDER BY sequence_name;
```

`LAST_NUMBER` đặc biệt cần hiểu đúng: với sequence có cache, đây có thể là mốc đầu của nhóm số cache tiếp theo, không luôn là số cuối cùng application đã dùng. Không dùng nó để suy luận chính xác ID vừa insert.

Nếu cần xem sequence schema khác mà bạn có quyền truy cập, dùng `ALL_SEQUENCES`; quyền DBA có thể dùng `DBA_SEQUENCES`.

## 11. Quyền cho schema khác

Object sequence thuộc schema tạo nó. Cấp quyền lấy số cho schema khác:

```sql
GRANT SELECT ON app_user.seq_products TO ducla11;
```

Schema `DUCLA11` gọi bằng tên đầy đủ:

```sql
SELECT app_user.seq_products.NEXTVAL
FROM dual;
```

Có thể tạo synonym để viết ngắn hơn, nhưng chỉ nên làm khi quy ước schema rõ ràng:

```sql
CREATE SYNONYM seq_products FOR app_user.seq_products;
```

## 12. Xóa sequence

```sql
DROP SEQUENCE seq_products;
```

Lệnh chỉ xóa object sequence, không xóa dữ liệu trong bảng. Các trigger, procedure hoặc application đang gọi sequence này sẽ lỗi sau khi xóa.

## 13. Checklist nhanh

- Primary key mới, đơn giản: cân nhắc `IDENTITY`.
- Cần sequence: dùng `NOCYCLE`, khai báo `CACHE` phù hợp và `NUMBER(19)` cho ID dài hạn.
- Không dùng `MAX(id) + 1`.
- Chấp nhận ID bị nhảy; không dùng sequence cho mã bắt buộc liên tiếp.
- Không restart/reset sequence khi chưa đối chiếu `MAX(id)` và luồng ghi đồng thời.
- Cấp tối thiểu quyền `SELECT` cho schema chỉ cần gọi `NEXTVAL`.
