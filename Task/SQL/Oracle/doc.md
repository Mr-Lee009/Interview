# Oracle Database - tài liệu thực hành

Tài liệu này dùng với Oracle XE 21c trong `docker-compose.yml`. Ví dụ kết nối:

```text
Host     : localhost
Port     : 1521
Service  : XEPDB1
User     : SYSTEM hoặc APP_USER
Password : OracleDev123 hoặc AppUser123
```

> Trong Oracle, **schema gắn với user**. User `APP_USER` sẽ có schema tên `APP_USER`.
> Không đặt tên bảng là `USER` vì đây là từ khóa/hàm đặc biệt; ví dụ dùng `USERS`.

## 1. Các nhóm kiểu dữ liệu chính

### Kiểu ký tự

| Kiểu | Dùng để lưu | Ví dụ |
|---|---|---|
| `VARCHAR2(n CHAR)` | Chuỗi thay đổi độ dài, tên, email, mã; nên dùng `CHAR` để tính theo ký tự | `VARCHAR2(150 CHAR)` |
| `CHAR(n CHAR)` | Chuỗi độ dài cố định, mã có độ dài chuẩn | `CHAR(2 CHAR)` cho mã quốc gia |
| `NVARCHAR2(n)` | Chuỗi Unicode theo national character set | `NVARCHAR2(100)` |
| `NCHAR(n)` | Unicode độ dài cố định | `NCHAR(2)` |
| `CLOB` | Văn bản rất dài, bài viết, JSON/XML dạng text | `CLOB` |
| `NCLOB` | Văn bản Unicode rất dài | `NCLOB` |

`VARCHAR2` là lựa chọn thông thường. Không dùng `CHAR` cho email/tên vì Oracle sẽ đệm khoảng trắng.

### Kiểu số

| Kiểu | Dùng để lưu | Ví dụ |
|---|---|---|
| `NUMBER(p,s)` | Tiền, số lượng, phần trăm, số thập phân chính xác | `NUMBER(12,2)` |
| `NUMBER(p)` | Số nguyên có giới hạn chữ số | `NUMBER(10)` |
| `FLOAT(p)` | Số dấu phẩy động; thực tế là một dạng `NUMBER` | `FLOAT( binary_precision )` |
| `BINARY_FLOAT` | Số thực 32-bit, tính toán nhanh, có thể sai số | `BINARY_FLOAT` |
| `BINARY_DOUBLE` | Số thực 64-bit, phù hợp tính toán khoa học | `BINARY_DOUBLE` |

Tiền và dữ liệu cần chính xác nên dùng `NUMBER`, không dùng `FLOAT`/`BINARY_*`.

### Ngày giờ và khoảng thời gian

| Kiểu | Dùng để lưu | Ví dụ |
|---|---|---|
| `DATE` | Ngày và giờ đến giây | ngày sinh, ngày tạo |
| `TIMESTAMP` | Ngày giờ có phần nhỏ hơn giây | log, thời điểm chính xác |
| `TIMESTAMP WITH TIME ZONE` | Ngày giờ kèm múi giờ | giao dịch toàn cầu |
| `TIMESTAMP WITH LOCAL TIME ZONE` | Oracle chuẩn hóa theo DB time zone và hiển thị theo session | ứng dụng đa múi giờ |
| `INTERVAL YEAR TO MONTH` | Khoảng cách theo năm/tháng | thời hạn hợp đồng |
| `INTERVAL DAY TO SECOND` | Khoảng cách theo ngày/giây | thời lượng xử lý |

`SYSDATE` trả về `DATE`; `SYSTIMESTAMP` trả về timestamp kèm múi giờ.

### Kiểu nhị phân và kiểu đặc biệt

| Kiểu | Dùng để lưu | Ghi chú |
|---|---|---|
| `RAW(n)` | Hash, mã nhị phân, token ngắn | tối đa 2,000 bytes trong bảng |
| `BLOB` | Ảnh, file PDF, dữ liệu nhị phân lớn | dữ liệu nằm trong DB |
| `BFILE` | File nhị phân bên ngoài DB | chỉ lưu đường dẫn, DB không quản lý nội dung |
| `ROWID` | Địa chỉ vật lý của dòng | không dùng làm khóa nghiệp vụ |
| `UROWID` | Rowid tổng quát, kể cả một số bảng đặc biệt | dùng hiếm |
| `JSON` | Tài liệu JSON có kiểm tra cú pháp | Oracle 21c hỗ trợ kiểu native |
| `XMLTYPE` | Tài liệu XML | cần dùng XML DB feature |
| `LONG`, `LONG RAW` | Kiểu cũ cho text/binary dài | không dùng cho thiết kế mới; dùng `CLOB`/`BLOB` |

Oracle còn có object type, collection (`VARRAY`, nested table), `ANYDATA`, `SDO_GEOMETRY` và các kiểu mở rộng theo option. Đây là các kiểu schema-level/feature-specific, không phù hợp để gom vào một bảng user thông thường.

## 2. Tạo schema/user

Chạy phần này bằng user có quyền DBA, ví dụ `SYSTEM`. Nếu container đã tạo sẵn `APP_USER` từ Compose thì bỏ qua lệnh `CREATE USER`.

```sql
-- Kết nối đúng PDB XEPDB1 trước khi tạo user ứng dụng.
ALTER SESSION SET CONTAINER = XEPDB1;

CREATE USER app_user IDENTIFIED BY AppUser123
	DEFAULT TABLESPACE USERS
	TEMPORARY TABLESPACE TEMP
	QUOTA 500M ON USERS;

GRANT CREATE SESSION, CREATE TABLE, CREATE SEQUENCE,
			CREATE VIEW, CREATE PROCEDURE, CREATE TRIGGER
TO app_user;
```

Đổi mật khẩu và quyền theo môi trường thật. Không cấp `DBA` cho user ứng dụng.

## 3. Tạo bảng `USERS` bao phủ kiểu dữ liệu

Bảng dưới đây cố ý chứa nhiều kiểu để học tập. Trong dự án thật, không nhất thiết phải sử dụng tất cả cột này.

```sql
CREATE TABLE app_user.users (
	user_id             NUMBER(19) GENERATED BY DEFAULT AS IDENTITY,
	username            VARCHAR2(50 CHAR) NOT NULL,
	full_name           NVARCHAR2(150),
	country_code        CHAR(2 CHAR) DEFAULT 'VN' NOT NULL,
	gender_code         NCHAR(1),
	email               VARCHAR2(255 CHAR) NOT NULL,
	password_hash       RAW(64) NOT NULL,
	salary              NUMBER(12,2),
	score               BINARY_FLOAT,
	credit_limit        BINARY_DOUBLE,
	birth_date          DATE,
	registered_at       TIMESTAMP(6) DEFAULT LOCALTIMESTAMP NOT NULL,
	last_login_at       TIMESTAMP(6) WITH TIME ZONE,
	profile_updated_at  TIMESTAMP(6) WITH LOCAL TIME ZONE,
	membership_period   INTERVAL YEAR(2) TO MONTH,
	last_session_length INTERVAL DAY(3) TO SECOND(6),
	avatar              BLOB,
	biography           CLOB,
	external_file       BFILE,
	preferences         JSON,
	profile_xml         XMLTYPE,
	physical_rowid      UROWID,
	status              VARCHAR2(20 CHAR) DEFAULT 'ACTIVE' NOT NULL,
	created_at          TIMESTAMP(6) DEFAULT SYSTIMESTAMP NOT NULL,
	updated_at          TIMESTAMP(6),

	CONSTRAINT pk_users PRIMARY KEY (user_id),
	CONSTRAINT uk_users_username UNIQUE (username),
	CONSTRAINT uk_users_email UNIQUE (email),
	CONSTRAINT ck_users_salary CHECK (salary IS NULL OR salary >= 0),
	CONSTRAINT ck_users_status CHECK (status IN ('ACTIVE', 'LOCKED', 'INACTIVE'))
);
```

Lưu ý:

- `XMLTYPE` có thể cần cài/enable XML DB trên môi trường Oracle cụ thể. Nếu chỉ cần JSON, có thể bỏ cột `profile_xml`.
- `BFILE` chỉ trỏ đến file ngoài DB; không thể upload file bằng `INSERT` text thông thường.
- `UROWID` thường để minh họa; không nên tự gán `physical_rowid`.
- Cột identity tự sinh `user_id`, nên khi insert thường không truyền cột này.

### Comment cho bảng và cột

```sql
COMMENT ON TABLE app_user.users IS 'Thông tin tài khoản người dùng';
COMMENT ON COLUMN app_user.users.user_id IS 'Khóa chính tự tăng';
COMMENT ON COLUMN app_user.users.password_hash IS 'Hash mật khẩu, không lưu mật khẩu dạng rõ';
COMMENT ON COLUMN app_user.users.preferences IS 'Tùy chọn người dùng ở định dạng JSON';
COMMENT ON COLUMN app_user.users.profile_xml IS 'Thông tin hồ sơ mở rộng ở định dạng XML';
```

Xem comment và cấu trúc:

```sql
SELECT column_id, column_name, data_type, data_length, nullable
FROM user_tab_columns
WHERE table_name = 'USERS'
ORDER BY column_id;

SELECT table_name, comments FROM user_tab_comments WHERE table_name = 'USERS';
SELECT column_name, comments FROM user_col_comments WHERE table_name = 'USERS';
```

## 4. Thêm dữ liệu - `INSERT`

```sql
INSERT INTO app_user.users (
	username, full_name, country_code, gender_code, email, password_hash,
	salary, score, credit_limit, birth_date, last_login_at,
	membership_period, last_session_length, preferences, status
) VALUES (
	'duc.le', N'Le Anh Duc', 'VN', N'M', 'duc@example.com',
	HEXTORAW('9F86D081884C7D659A2FEAA0C55AD015'),
	2500.50, 98.5, 10000.75, DATE '1995-08-25',
	TO_TIMESTAMP_TZ('2026-08-25 09:30:00 +07:00', 'YYYY-MM-DD HH24:MI:SS TZH:TZM'),
	INTERVAL '1-6' YEAR TO MONTH,
	INTERVAL '0 02:15:30.500' DAY TO SECOND,
	JSON('{"theme":"dark","language":"vi"}'), 'ACTIVE'
);

INSERT INTO app_user.users (username, full_name, email, password_hash)
VALUES ('lan.nguyen', N'Nguyen Thi Lan', 'lan@example.com', HEXTORAW('AABBCCDD'));

COMMIT;
```

`NULL` nghĩa là chưa có giá trị; không dùng `= NULL`, phải dùng `IS NULL`.

## 5. CRUD cơ bản

```sql
-- C (Create): thêm một user
INSERT INTO app_user.users (username, full_name, email, password_hash)
VALUES ('minh.tran', N'Tran Van Minh', 'minh@example.com', HEXTORAW('01020304'));

-- R (Read): đọc dữ liệu
SELECT user_id, username, full_name, email, status, created_at
FROM app_user.users
WHERE status = 'ACTIVE'
ORDER BY created_at DESC;

-- U (Update): cập nhật có điều kiện
UPDATE app_user.users
SET full_name = N'Tran Van Minh Updated',
		updated_at = SYSTIMESTAMP
WHERE username = 'minh.tran';

-- D (Delete): xóa đúng dòng cần xóa
DELETE FROM app_user.users
WHERE username = 'minh.tran';

COMMIT; -- xác nhận INSERT/UPDATE/DELETE
-- ROLLBACK; -- dùng trước COMMIT nếu muốn hủy thay đổi
```

## 6. Query giới hạn và phân trang

### Lấy tối đa N dòng

```sql
-- Oracle 12c trở lên
SELECT user_id, username, created_at
FROM app_user.users
ORDER BY created_at DESC
FETCH FIRST 10 ROWS ONLY;

-- Điều kiện giới hạn số dòng
SELECT user_id, username, salary
FROM app_user.users
WHERE status = 'ACTIVE'
ORDER BY salary DESC NULLS LAST
FETCH FIRST 5 ROWS WITH TIES;
```

### Phân trang bằng `OFFSET ... FETCH`

```sql
-- Trang 3, mỗi trang 10 dòng: bỏ 20 dòng đầu, lấy 10 dòng tiếp theo
SELECT user_id, username, email, created_at
FROM app_user.users
ORDER BY created_at DESC, user_id DESC
OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY;
```

Luôn có `ORDER BY` ổn định khi phân trang, nên thêm khóa chính để tránh thứ tự không xác định.

### Cách tương thích Oracle cũ: `ROWNUM`

```sql
SELECT *
FROM (
	SELECT u.user_id, u.username, u.created_at
	FROM app_user.users u
	ORDER BY u.created_at DESC, u.user_id DESC
)
WHERE ROWNUM <= 10;
```

Không viết `WHERE ROWNUM > 10` trực tiếp vì `ROWNUM` được gán trước khi Oracle sắp xếp/đánh số theo cách nhiều người kỳ vọng. Với Oracle 12c+, ưu tiên `OFFSET ... FETCH`.

## 7. Query JSON, thời gian và thống kê

```sql
-- Đọc một thuộc tính JSON
SELECT username, JSON_VALUE(preferences, '$.language') AS language
FROM app_user.users
WHERE JSON_VALUE(preferences, '$.language') = 'vi';

-- Lọc theo ngày, dùng khoảng nửa kín để không mất dữ liệu trong ngày
SELECT username, registered_at
FROM app_user.users
WHERE registered_at >= TIMESTAMP '2026-01-01 00:00:00'
	AND registered_at <  TIMESTAMP '2027-01-01 00:00:00';

-- Đếm và nhóm
SELECT status, COUNT(*) AS total_users, AVG(salary) AS average_salary
FROM app_user.users
GROUP BY status
ORDER BY total_users DESC;
```

## 8. Xóa bảng và kiểm tra quyền

```sql
-- Cẩn thận: xóa cả cấu trúc và dữ liệu
DROP TABLE app_user.users PURGE;

-- Kiểm tra bảng trong schema hiện tại
SELECT table_name FROM user_tables WHERE table_name = 'USERS';

-- Nếu đang dùng SYSTEM để xem object của APP_USER
SELECT owner, object_name, object_type
FROM all_objects
WHERE owner = 'APP_USER' AND object_name = 'USERS';
```

Kiểm tra container:

```powershell

docker compose ps

```

Chờ trạng thái healthcheck là `healthy` rồi mới chạy lệnh SQL. Không dùng `docker compose down -v` nếu muốn giữ lại dữ liệu trong volume `oracle-data`.
