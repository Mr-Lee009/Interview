Kết nối WebSocket trực tiếp
  • 1. Mở kết nối & ulimit OS
    Tăng giới hạn File Descriptors (`ulimit -n 1000000`). Load Balancer điều phối bằng thuật toán Least Connections.
  • 2. WebFlux & Non-blocking
    Ứng dụng dùng Spring WebFlux (Netty) với Event Loop. Một thread có thể gánh hàng ngàn kết nối nhàn rỗi mà không treo RAM.
  • 3. Gửi tin & Publish (Redis)
    User A gửi tin nhắn cho B. Node #1 nhận tin và Publish message đó vào Redis channel chung.
  • 4. Subscribe & Đẩy tin xuống
    Node #2 (đang Subscribe Redis) nhận được tin, kiểm tra thấy User B đang kết nối tại máy mình -> đẩy qua WebSocket.
  • 5. Xử lý khi User Offline
    Nếu B offline, tin nhắn được lưu vào Database ở trạng thái UNREAD và kích hoạt Push Notification (FCM/APNs).
Điểm mạnh
  • Không tốn Thread: Nhờ kiến trúc Non-blocking I/O (WebFlux/Netty), hệ thống giải quyết vấn đề cạn kiệt Thread của Tomcat cũ.
  • Scale ngang vô hạn: Dễ dàng cắm thêm Node mới vào sau Load Balancer.
  • Tính nhất quán cao: Dữ liệu trạng thái đồng bộ mượt mà qua Redis Pub/Sub.
Lưu ý vận hành
  • Tầng Hệ điều hành: Bắt buộc cấu hình lại `ulimit -n` và các tham số `sysctl` liên quan đến `tcp_max_syn_backlog`, `TIME_WAIT`.
  • Header Upgrade: Load Balancer phải được cấu hình cho phép truyền header Connection: Upgrade để duy trì TCP.
  • Heartbeat (Ping/Pong): Cần cơ chế phát hiện ngắt mạng ngầm (Client chết nhưng OS chưa báo).
