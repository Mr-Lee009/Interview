Xác thực khi mở WebSocket

Hiểu cách xác thực user ở lúc handshake bằng session cookie, JWT, header token hoặc query param. Đây là nền tảng trước khi đi tiếp sang phân quyền và scale.

Q11

Scale chat lên 100.000 kết nối

Đây là case tổng hợp: giữ nhiều connection, đồng bộ message giữa nhiều Spring Boot node, lưu offline message và tổ chức kiến trúc để không dồn toàn bộ state vào một instance.

Gợi ý thứ tự học: nên đi từ Q7 → Q8 → Q10 → Q11. Cách này giúp mình xây nền trước, rồi mới nối sang bài toán multi-node, reliability và cuối cùng là scale lớn.

Điểm cần nắm

  • 1. Auth ở handshake WebSocket thường xác thực 1 lần khi mở kết nối, sau đó dùng session/context đã bind để xử lý message.
  • 2. Multi-node cần broker Nếu nhiều node mà chỉ broadcast local trong RAM, client ở node khác sẽ không nhận được event.
  • 3. Reconnect chưa đủ Client phải báo mốc cuối cùng đã nhận để server replay phần message còn thiếu.
  • 4. Scale lớn phải tách trách nhiệm Tách riêng xử lý kết nối, phân phối message và lưu trữ message để tránh một node ôm quá nhiều việc.
