ELK là gì và kiến trúc hoạt động ra sao?

ELK là bộ công cụ dùng để thu thập, xử lý, lưu trữ, tìm kiếm và trực quan hóa log hoặc dữ liệu sự kiện. Trong thực tế, hệ thống thường mở rộng thêm Beats, vì vậy nhiều nơi gọi đầy đủ là Elastic Stack.

ELK phục vụ công việc gì?

ELK phục vụ các bài toán quan sát hệ thống và khai thác dữ liệu vận hành. Mục tiêu cốt lõi là biến log từ dữ liệu thô thành dữ liệu có thể tra cứu, phân tích và trực quan hóa được.

  • Tập trung log từ nhiều server, nhiều service, nhiều môi trường.
  • Tìm kiếm log nhanh khi hệ thống có lỗi.
  • Phân tích nguyên nhân sự cố theo thời gian thực hoặc gần thời gian thực.
  • Theo dõi hành vi hệ thống, hiệu năng và cảnh báo bất thường.
  • Hỗ trợ audit, security monitoring và troubleshooting.
  • Tạo dashboard cho vận hành, DevOps, backend, security hoặc business analytics.
Ví dụ: khi API lỗi 500, ta có thể search theo traceId, userId hoặc orderId để lần ngược toàn bộ luồng xử lý.

Vì sao ELK quan trọng?

  • Nếu không có ELK, log thường nằm rải rác trên nhiều máy.
  • Việc debug phải SSH vào từng server, rất chậm và khó đối chiếu.
  • Khó nối log giữa các service trong kiến trúc microservices.
  • Khó nhìn được bức tranh toàn cảnh giữa ứng dụng, hạ tầng và người dùng.
Nói ngắn gọn, ELK là cầu nối giữa dữ liệu vận hành và khả năng ra quyết định trong debugging, monitoring và audit.

Kiến trúc tổng quát của ELK

Thu thập dữ liệu
Xử lý dữ liệu
Lưu trữ và tìm kiếm
Trực quan hóa
Agent nhẹ

Beats

Beats là các agent nhẹ dùng để đẩy log, metric hoặc network data về Elastic Stack.

  • Filebeat: ship log file
  • Metricbeat: ship metric hệ thống
  • Packetbeat: ship network data
  • Winlogbeat: ship Windows event log
Ingest pipeline

Logstash

Logstash nhận dữ liệu từ nhiều nguồn, chuẩn hóa và enrich dữ liệu trước khi ghi sang nơi lưu trữ.

  • input: nhận dữ liệu
  • filter: parse, transform, enrich
  • output: ghi ra Elasticsearch hoặc đích khác
Lõi tìm kiếm

Elasticsearch

Elasticsearch là nơi lưu trữ document JSON và trả lời truy vấn tìm kiếm, filter, aggregate với tốc độ cao.

  • Full-text search
  • Filter theo trường
  • Aggregation thống kê
  • Cluster, shard, scale ngang
Giao diện phân tích

Kibana

Kibana là nơi con người làm việc trực tiếp với dữ liệu: search log, xem timeline, dashboard và cảnh báo.

  • Khám phá log theo UI
  • Dashboard và chart
  • Phân tích theo thời gian
  • Alert nếu hệ thống có cấu hình phù hợp

ELK hỗ trợ ai?

  • Backend Developer: tra cứu lỗi, đối chiếu log giữa nhiều service
  • DevOps/SRE: vận hành, monitoring, incident response
  • Security: audit log, phát hiện bất thường
  • Business/Product: xem event nghiệp vụ nếu log có cấu trúc phù hợp

Điểm mạnh

  • Tìm kiếm log mạnh và nhanh
  • Hỗ trợ gần thời gian thực
  • Kibana trực quan
  • Hệ sinh thái rộng, phổ biến trong vận hành hệ thống

Lưu ý khi triển khai

  • Chi phí tài nguyên, đặc biệt là Elasticsearch
  • Quản trị index, shard, retention, lifecycle
  • Chuẩn hóa format log ngay từ đầu
  • Monitoring cho chính cụm ELK
